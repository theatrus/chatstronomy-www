A Discord bot for your telescope.

Observatory notifications and control in chat

Chatstronomy monitors your N.I.N.A. rigs and posts real-time updates to a chat channel. It posts each capture, autofocus run, guiding graph, and status change. You can run slash commands to check on the rig, or to control it.

Open Chatstronomy Hub Install the N.I.N.A. plugin

The software supports N.I.N.A. 3.2+ on Windows, runs on standalone Windows and Linux backends, and is licensed under Apache-2.0.

The Chatstronomy plugin is built into N.I.N.A.

The plugin reads N.I.N.A. natively, renders guider and autofocus graphs, sends the event families you choose, and exposes approved bot commands. No N.I.N.A. web server or polling setup is required.

The Chatstronomy Hub is the recommended setup.

Pair the plugin with Chatstronomy Hub for the simplest setup. Each N.I.N.A. machine connects outbound over authenticated WSS, so one centralized Discord or Matrix bot can serve rigs on different systems without opening observatory ports or copying chat credentials to every computer.

Local Direct mode keeps all operations local.

You can run the integration entirely on the observatory computer using a Discord webhook, a custom Discord application, or a Matrix account on an HTTPS homeserver. The plugin starts its signed, release-pinned Chatstronomy runtime in the background and supplies N.I.N.A. data directly.

You can install the plugin from the N.I.N.A. plugin manager.

  1. Open Plugins > Available, find Chatstronomy, install it, and restart N.I.N.A. once it appears in the official repository.
  2. For the current release from our development repository, open Options > General > Plugin Repositories, select +, and add https://raw.githubusercontent.com/theatrus/chatstronomy-nina-plugin/main/registry.
  3. Return to Plugins > Available, install Chatstronomy, and restart N.I.N.A.
  4. Open Chatstronomy Hub, create a pairing code, then choose Chatstronomy.com — hosted bot in the plugin and pair the rig.

N.I.N.A. supports more than one plugin repository, so adding the development repository does not replace the official one. It serves the current tagged package without a separate beta channel. Both the release-pinned runtime and Chatstronomy.dll are signed and verified before publication. See the plugin repository for current installation details.

The plugin sends telemetry updates to the chat channel.

These notifications provide enough information to track the session without opening a remote desktop.

The bot posts every sub-exposure as it is captured.

New captures are posted as full-size previews with metadata including the filter, exposure duration, and target. You can configure a cooldown interval to prevent a fast sequence from flooding the channel.

The bot sends autofocus and guiding charts.

Autofocus runs are sent as plotted curves, and guiding data is sent as a graph. These charts allow you to monitor focusing and tracking performance during the session.

The bot reports live status updates.

Status updates include Sequence and Target Scheduler targets, cooling progress, timed-wait status, slewing events, and centering results. The bot also tracks mount state, meridian flips, equipment telemetry, N.I.N.A. notifications, and optional logs.

The Hub supports multiple rigs.

You can pair multiple N.I.N.A. instances on different systems with a single centrally managed bot, and then route each telescope's telemetry to a dedicated channel or room.

The plugin generates visual telemetry graphs.

Control the telescope using slash commands.

You can query the current status of your equipment and, when control features are enabled, issue commands directly from chat.

  • /status
  • /sequence
  • /target
  • /mount
  • /last-image
  • /autofocus
  • /guider
  • /events
  • /park
  • /unpark
  • /home
  • /cool
  • /change-filter
  • /abort-capture
  • /stop-sequence

The plugin provides twenty-one commands in total; the read-only commands do not require special permissions.

Control features are disabled by default. By default, the bot only sends telemetry notifications and does not execute commands. Enabling control features allows users to operate telescope hardware remotely through chat channels.

Commands that modify equipment state are restricted to authorized Discord accounts, and critical commands require explicit confirmation. Users must evaluate the security implications of managing equipment through chat integrations. The Terms of Service details these considerations.

You can select your deployment topology.

The Chatstronomy Hub topology is recommended.

This option pairs multiple N.I.N.A. installations with a centrally managed bot. The observatory computers make outbound connections over WebSockets, which eliminates the need to expose N.I.N.A. or local ports to the internet. Open the Hub to begin.

The local host topology is available now.

You can configure the N.I.N.A. plugin to run in Direct mode using a local Discord webhook, a custom Discord application, or a Matrix account. This approach does not route data through external servers, and the plugin manages the local background runtime automatically.
