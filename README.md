# chatstronomy-www

This repository contains the marketing and documentation website for **[chatstronomy.com](https://chatstronomy.com/)**. Chatstronomy is the rebranded version of [theatrus/spacecat](https://github.com/theatrus/chatstronomy), which is a N.I.N.A. observing assistant. It reports imaging session status to Discord and Matrix, and it can optionally accept control commands from a chat channel.

The website consists of static HTML and requires no build step. It is served by
nginx on the AWS-hosted seiza server from `/www/chatstronomy.com`, a checkout of
this repository. Amazon CloudFront sits in front of both the marketing site and
the separately routed Chatstronomy Hub. Pushing changes to `main` triggers a
flotswarm deployment and invalidates the marketing site's CloudFront cache.

| Property | Configuration |
|---|---|
| Host and docroot | AWS-hosted seiza server; nginx serves `/www/chatstronomy.com`. |
| Deploy | Flotswarm action `deploy-chatstronomy-www` updates the checkout and invalidates CloudFront. |
| Public TLS | Amazon CloudFront uses an AWS Certificate Manager certificate for the site and Hub hostnames. |
| DNS | Porkbun DNS points the site and Hub hostnames to their CloudFront distributions. |
| Infrastructure | Defined in `tfinfra/roots/seiza`; see `tfinfra/docs/chatstronomy-hub.md`. |

## Contents

| Path | Description |
|---|---|
| `index.html` | This file contains the main landing page. |
| `terms.html` | Terms for the self-hosted Chatstronomy application. |
| `privacy.html` | Privacy policy for the self-hosted application and marketing website. |
| `hub-terms.html` | Terms for the hosted Chatstronomy Hub service. |
| `hub-privacy.html` | Privacy, processing, infrastructure, retention, and deletion policy for the hosted Hub. |
| `assets/` | This directory contains images and the site favicon. |

Branding assets are sourced from `theatrus/chatstronomy` under `assets/branding/` to maintain consistent artwork across all interfaces. The file `assets/logo.png` is the transparent master image, `favicon.ico` contains the required Windows sizes, and the graph assets are actual outputs generated by the application.

The landing page tracks the development of the separately released [`theatrus/chatstronomy-nina-plugin`](https://github.com/theatrus/chatstronomy-nina-plugin), which provides native N.I.N.A. integration, configurable events and logs, local Discord/Matrix delivery, and multi-machine pairing via the recommended [Chatstronomy Hub](https://hub.chatstronomy.com/). You can install the plugin through N.I.N.A.'s plugin manager by using the built-in official repository or by adding the development repository registry URL:

`https://raw.githubusercontent.com/theatrus/chatstronomy-nina-plugin/main/registry`

The installation notes must remain accurate. The development repository serves the current tagged package without a separate beta channel. Plugin tags are used to sign and verify both the pinned Rust runtime and the `Chatstronomy.dll` library before packaging.

The files `terms.html` and `privacy.html` describe only self-hosted software.
The public managed service has separate, directly linkable policies at
`/hub-terms.html` and `/hub-privacy.html`. Link the hosted policies from the Hub,
its N.I.N.A. pairing flow, and Discord application settings where the hosted
service is the application being described.

## The source files are plain HTML files.

The project contains plain files and does not use a generator or npm. Existing
marketing and self-hosted policy pages include their Google Analytics tag
directly. The hosted Hub policies intentionally do not load analytics scripts;
they should remain readable without tracking or accepting marketing cookies.


## Hosted policies must match the actual service.

The Hub stores Discord identity, telescope configuration, routing, session,
credential, and management-audit records. It processes live observatory events,
images, and optionally selected logs even when some events are suppressed from
chat. Its AWS-hosted SQLite database is backed up hourly to private, encrypted,
versioned S3 storage; older backup versions expire after 90 days. Account
deletion is currently a manual request, and administrative audit history has no
fixed automatic retention schedule.

Hardware-changing commands are disabled by default and must be explicitly
enabled in the local N.I.N.A. profile. Hub roles and permissions add
restrictions but cannot grant local consent. Sharing observatory coordinates and
location-derived mount data is also off by default; hardware device and driver
identifiers are always redacted. Keep both hosted policy documents accurate
when equipment privacy controls, retention, infrastructure, supported providers,
command handling, or deletion workflows change.
