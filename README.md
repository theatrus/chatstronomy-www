# chatstronomy-www

This repository contains the marketing and documentation website for **[chatstronomy.com](https://chatstronomy.com/)**. Chatstronomy is the rebranded version of [theatrus/spacecat](https://github.com/theatrus/chatstronomy), which is a N.I.N.A. observing assistant. It reports imaging session status to Discord and Matrix, and it can optionally accept control commands from a chat channel.

The website consists of static HTML and requires no build step. It is served by nginx on ec2admin from the directory `/www/chatstronomy.com`, which contains a checkout of this repository. Pushing changes to the `main` branch triggers a deployment via a flotswarm webhook.

| Property | Configuration |
|---|---|
| Docroot | The document root is located at `/www/chatstronomy.com`. |
| Deploy | Deployments are managed by the flotswarm action `deploy-chatstronomy-www`. |
| TLS | TLS certificates are managed per-site via Let's Encrypt using a certbot timer. |
| DNS | DNS is configured via Porkbun with A/AAAA records pointing to ec2admin, defined in `tfinfra roots/porkbun/chatstronomy-com.tf`. |

## Contents

| Path | Description |
|---|---|
| `index.html` | This file contains the main landing page. |
| `terms.html` | This file contains the terms of service for the Discord application. |
| `privacy.html` | This file contains the privacy statement, which is separately linkable. |
| `assets/` | This directory contains images and the site favicon. |

Branding assets are sourced from `theatrus/chatstronomy` under `assets/branding/` to maintain consistent artwork across all interfaces. The file `assets/logo.png` is the transparent master image, `favicon.ico` contains the required Windows sizes, and the graph assets are actual outputs generated by the application.

The landing page tracks the development of the separately released [`theatrus/chatstronomy-nina-plugin`](https://github.com/theatrus/chatstronomy-nina-plugin), which provides native N.I.N.A. integration, configurable events and logs, local Discord/Matrix delivery, and multi-machine pairing via the recommended [Chatstronomy Hub](https://hub.chatstronomy.com/). You can install the plugin through N.I.N.A.'s plugin manager by using the built-in official repository or by adding the development repository registry URL:

`https://raw.githubusercontent.com/theatrus/chatstronomy-nina-plugin/main/registry`

The installation notes must remain accurate. The development repository serves the current tagged package without a separate beta channel. Plugin tags are used to sign and verify both the pinned Rust runtime and the `Chatstronomy.dll` library before packaging.

The files `terms.html` and `privacy.html` are required by Discord's application settings, which demand a Terms of Service URL and a Privacy Policy URL before an application can be verified or listed. These pages currently describe only the self-hosted software and do not cover the hosted Hub service.

## The source files are plain HTML files.

The project contains plain files and does not use a generator or npm. Analytics scripts and the cross-site menu bar are injected by nginx using shared snippets, so you should not add these tags directly to the HTML files (refer to `tfinfra docs/www-sites.md` for more details).


## The Chatstronomy Hub requires dedicated service terms.

The files `terms.html` and `privacy.html` state that the application does not communicate with our servers, which is only true for the self-hosted version. Both pages are scoped specifically to the self-hosted application and indicate that a hosted service is planned, meaning neither page covers the hosted Hub.

Before launching the public hosted service, the Hub requires dedicated terms and a privacy statement. At a minimum, these documents must specify data storage details, retention periods, hosting environments, data access permissions, account closure procedures, and the security implications of a service compromise on connected equipment. Since the Hub can relay control commands, any security compromise introduces equipment risks similar to those described under the telescope control section, with our infrastructure acting as an intermediary path.
