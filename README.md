# chatstronomy-www

This repository contains the marketing and documentation website for
**[chatstronomy.com](https://chatstronomy.com/)**. Chatstronomy is an observing
assistant for N.I.N.A. The hosted Hub sends selected updates to Discord; a
local runtime supports Discord or Matrix. Optional equipment commands require
explicit approval in the N.I.N.A. plugin.

The website consists of static HTML and requires no build step. It is served by
nginx on the AWS-hosted seiza server from `/www/chatstronomy.com`, a checkout of
this repository. Amazon CloudFront sits in front of both the marketing site and
the separately routed Chatstronomy Hub. Pushing changes to `main` triggers a
flotswarm deployment and invalidates the marketing site's CloudFront cache.

| The configuration property. | The configuration details. |
|---|---|
| The host and document root. | The website is hosted on the AWS-hosted seiza server, where nginx serves it from the `/www/chatstronomy.com` directory. |
| The deployment process. | The Flotswarm action `deploy-chatstronomy-www` updates the repository checkout and invalidates the CloudFront cache. |
| The public TLS certificate. | Amazon CloudFront uses an AWS Certificate Manager certificate for the website and Hub hostnames. |
| The DNS configuration. | Porkbun DNS points the website and Hub hostnames to their respective CloudFront distributions. |
| The infrastructure definition. | The infrastructure is defined in the `tfinfra/roots/seiza` directory. You can read the `tfinfra/docs/chatstronomy-hub.md` file for details. |

## The repository contains the following directories and files.

| The file or directory path. | The description of the path. |
|---|---|
| `index.html` | This file contains the main landing page. |
| `terms.html` | This file contains the terms of service for the self-hosted Chatstronomy application. |
| `privacy.html` | This file contains the privacy policy for the self-hosted application and the marketing website. |
| `hub-terms.html` | This file contains the terms of service for the hosted Chatstronomy Hub. |
| `hub-privacy.html` | This file contains the privacy, data processing, infrastructure, retention, and deletion policies for the hosted Hub. |
| `assets/` | This directory contains images and the site favicon. |

Branding assets are sourced from `theatrus/chatstronomy` under `assets/branding/` to maintain consistent artwork across all interfaces. The file `assets/logo.png` is the transparent master image, `favicon.ico` contains the required Windows sizes, and the graph assets are actual outputs generated by the application.

The landing page tracks the separately released
[`theatrus/chatstronomy-nina-plugin`](https://github.com/theatrus/chatstronomy-nina-plugin),
which provides native N.I.N.A. integration, local Discord or Matrix delivery,
and multi-machine Discord pairing through the recommended
[Chatstronomy Hub](https://hub.chatstronomy.com/). Install the plugin from
N.I.N.A.'s official repository once it is listed there, or add our development
repository URL:

`https://raw.githubusercontent.com/theatrus/chatstronomy-nina-plugin/main/registry`

The installation notes must remain accurate. The development repository serves the current tagged package without a separate beta channel. Plugin tags are used to sign and verify both the pinned Rust runtime and the `Chatstronomy.dll` library before packaging.

The files `terms.html` and `privacy.html` describe only self-hosted software.
The public managed service has separate, directly linkable policies at
`/hub-terms.html` and `/hub-privacy.html`. Link the hosted policies from the Hub,
its N.I.N.A. pairing flow, and Discord application settings where the hosted
service is the application being described.

## The source files are plain HTML files.

The project contains plain files and does not use a generator or npm. Existing
marketing and self-hosted policy pages include their Google Analytics tag
directly. The hosted Hub policies intentionally do not load analytics scripts;
they should remain readable without tracking or accepting marketing cookies.


## Published policies must match the actual product.

The Hub supports Discord; Matrix requires a local runtime. The Hub stores
Discord identity, telescope configuration, routing, session, credential, and
management-audit records. It processes permitted observatory events, equipment
telemetry, images, and explicitly selected log levels. Ordinary event
categories, image delivery, and N.I.N.A. popup notifications start enabled;
users should review them before pairing or starting a local runtime. Event
switches are local transmission boundaries: disabled event families, including
previously buffered records, never reach either the hosted Hub or local runtime.
Events captured while a family is disabled cannot be released later; there is no
state-maintenance exception. Disabling images also prevents image history,
previews, thumbnails, and automatic image delivery, including previously
captured images. Other permitted events, equipment-status snapshots, and
explicitly requested non-image slash-command data remain available. Raw N.I.N.A.
logs start disabled and require a separate opt-in for each level. Its AWS-hosted
SQLite database is backed up hourly to private, encrypted, versioned S3 storage;
older backup versions expire after 90 days. Account deletion is currently a
manual request, and administrative audit history has no fixed automatic
retention schedule.

The hardware-control master switch and every individual equipment-command
permission default to off in each local N.I.N.A. profile. An equipment command
requires both permissions; enabling the master switch alone grants no commands.
Skipping sequence validation requires its own additional local permission. Hub
roles and permissions can add restrictions but cannot grant local consent.
Sharing observatory coordinates and location-derived mount data is also off by
default; hardware device and driver identifiers are always redacted. Keep both
hosted and self-hosted policy documents accurate when equipment privacy
controls, retention, infrastructure, supported providers, command handling, or
deletion workflows change. Self-hosted credentials belong in Windows Credential
Manager, not in plaintext N.I.N.A. profile settings. With no explicit local
Discord user allowlist, only server managers issuing requests from the
telescope's configured Discord channel can request locally approved commands;
an explicit allowlist replaces that manager fallback.
