These terms of service govern self-hosted Chatstronomy.

This document was last updated on 16 August 2026.

These terms cover only the Chatstronomy software you run on your own computer. That self-hosted application has no account to sign up for. The separately operated Chatstronomy Hub is not covered by these terms.

1. Chatstronomy is a telemetry and control integration for telescopes.

Chatstronomy is a chat bot designed for telescope integration. The software monitors a N.I.N.A. imaging session and posts real-time status updates, including image captures and autofocus results, to a Discord or Matrix channel. If enabled, the software can also accept slash commands from the chat channel and transmit them to the telescope equipment.

You are responsible for installing the software, supplying the Discord bot token or Matrix credentials, and configuring the connection to your equipment. The software runs locally under your control, on your hardware and network. For the self-hosted version covered by these terms, no data is routed through servers operated by us.

The separately managed Chatstronomy Hub coordinates connections across multiple observatories and routes telemetry through a hosted service we operate. The Hub requires its own hosted-service terms of service. These self-hosted terms do not apply to the Hub, and they do not describe the data storage or retention policies of the Hub.

The source code is published under the Apache License 2.0 at github.com/theatrus/chatstronomy. Those license terms govern the software itself, whereas these terms govern your use of the application.

2. We do not collect or store user data.

The self-hosted application does not communicate with our servers, which means we do not collect, store, share, or lose any user information. There are no built-in telemetry features, application analytics, crash reporting systems, license checks, or user accounts.

All application data is stored locally on your machine, including N.I.N.A. profile settings, credentials in the Windows credential store, and a small state file that tracks active chat message identifiers. This state file allows the bot to update existing status posts instead of creating duplicate entries. Removing the application and these local files deletes all associated data. You can refer to the Privacy Policy for more details.

3. The application transmits telemetry data to third-party chat services.

The application transmits only the data that you configure it to post. Telemetry data, such as images, session status, equipment readings, and text notifications, is transmitted directly to Discord or Matrix. Once transmitted, this data is subject to the respective service's terms and conditions. The bot establishes a direct connection to these services, so we cannot access, retrieve, or delete any of your sent data.

You should assume that any shared chat channel can be viewed by other users. Astronomical images frequently contain metadata headers that specify equipment details and capture coordinates, and channel membership may change over time. You are responsible for determining what data is safe to post and selecting the appropriate destination channels.

Your usage of Discord is governed by the Discord Terms of Service, and your usage of Matrix is subject to the terms of your selected homeserver.

4. Telescope control features present security and operational risks.

You must review security implications before enabling command execution. Chatstronomy can relay slash commands to your equipment. Enabling this functionality allows users to control physical hardware remotely through chat channels without local supervision.

Telescope control is disabled by default. The default installation only posts telemetry notifications and does not execute actions. Once enabled, available slash commands include parking or unparking the mount, aborting captures, and starting, pausing, or stopping sequences.

The system provides two security safeguards, and you should understand their limitations:

  • The application implements an authorized user allowlist. Only the specific Discord user IDs you configure are permitted to issue control commands. You are responsible for maintaining this list, as unauthorized or compromised accounts on the list will retain control permissions.
  • Destructive commands require explicit confirmation. Commands such as parking, aborting a capture, or stopping a sequence require an initial button press confirmation. This mechanism prevents accidental command execution but does not block authorized malicious actions.

Neither safeguard eliminates the fundamental risk: the physical safety of your equipment depends on the security of your third-party chat accounts. If an authorized Discord account is compromised, a bot token is leaked, or the bot is invited to an unverified channel, any user with access can execute commands allowed by your authorization list.

You must evaluate the potential consequences of incorrect command execution on your specific hardware. Unwanted mount movements, such as slewing or unparking, can cause physical collisions, cable wraps, or optical damage. Aborting a capture or stopping a sequence can result in data loss or lost imaging time. The chat interface has no awareness of local physical conditions, such as roof status, daylight, or local personnel.

Therefore, you should enable control features only if you accept these operational risks. It is recommended to restrict the allowlist to essential accounts, secure those accounts, and ensure that your physical and software safety limits, such as horizon limits, meridian limits, and roof interlocks, are fully configured and functional. Hardware and safety controller limits are the primary mechanisms for protecting equipment from damage.
